# NexLearn — Live deployment (free, no credit card)

This deploys NexLearn so **anyone can open a link and use the app — no installation**.

Target stack (all free tiers, no payment method required anywhere):

| Piece | Service | What it is |
|---|---|---|
| Frontend (Next.js) | **Vercel** Hobby | `https://your-app.vercel.app` |
| Backend (Express + Bun) | **Render** Free | `https://your-service.onrender.com` |
| Database | **MongoDB Atlas** M0 | 512 MB free cluster |

How it fits together: the browser talks only to Vercel. Vercel proxies
`/api/*` to Render (see the rewrite in `frontend/next.config.mjs`), so the
session cookie stays first-party and no CORS/third-party-cookie problems
occur.

---

## Step 1 — MongoDB Atlas (database)

1. Create a free account at <https://cloud.mongodb.com>.
2. Create an **M0 Free** cluster (closest region to you, e.g. `ap-south-1`).
3. Database Access → **Add Database User** → user + password (Copy+Paste "Autogenerate", save it).
4. Network Access → **Add IP Address** → `0.0.0.0/0` (Render free instances have no fixed outbound IPs).
5. Database → **Connect → Drivers** → copy the connection string:

   ```
   MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/nexlearn?retryWrites=true&w=majority
   ```

   Replace `<user>` / `<password>` and keep the URL-encoded password (e.g. `@` → `%40`).

## Step 2 — Backend on Render

1. Push this repo to GitHub (Render deploys from GitHub).
2. Go to <https://dashboard.render.com> → **New → Blueprint** → pick the NexLearn repo.
   Render reads `render.yaml` (docker runtime, Bun, health check `/api/health`).
3. After the first deploy finishes, open the service → **Environment** and set:
   - `MONGODB_URI` = the Atlas string from Step 1
   - `FRONTEND_URL` = `https://<your-vercel-app>.vercel.app` (from Step 3)
4. Note your backend URL: `https://<your-service>.onrender.com`.
5. Verify: open `https://<your-service>.onrender.com/api/health` → expect
   `{"ok":true,"service":"nexlearn-backend"}`.

`JWT_SECRET` is auto-generated by Render (`generateValue: true` in
`render.yaml`) — no manual step needed.

## Step 3 — Frontend on Vercel

1. Go to <https://vercel.com> → **Add New → Project** → import the repo.
2. Before deploy set (**Build → Environment Variables**):
   - `BACKEND_URL` = `https://<your-service>.onrender.com`
3. Deploy. Vercel auto-detects Next.js (root directory = `frontend/`).
4. Verify: open `https://<your-app>.vercel.app` → landing page loads,
   and signing up/logging in works (it calls `/api/...` through the proxy).

Done — that link is your live app. Anyone can open it; nothing to install.

## Environment variables (summary)

| Where | Variable | Notes |
|---|---|---|
| Render (backend) | `MONGODB_URI` | Atlas string, secret |
| Render (backend) | `FRONTEND_URL` | Your Vercel URL (CORS allowlist) |
| Render (backend) | `JWT_SECRET` | Auto-generated by `render.yaml` |
| Render (backend) | `NODE_ENV` | `production` (set by `render.yaml`) |
| Vercel (frontend) | `BACKEND_URL` | Your Render URL — server-side only, never exposed to the browser |

Optional (add later, app degrades gracefully when unset): `GOOGLE_CLIENT_ID`
(sign-in), `GROQ_API_KEY` / `OPENROUTER_API_KEY` (AI helper), Appwrite
variables (avatars).

## Free-tier limits (be aware)

- **Render free**: sleeps after ~15 min of inactivity. First request after a
  nap takes ~30–60 s (cold start) — the app shows a timeout, then works.
  750 free instance-hours/month is enough for light use.
- **Atlas M0**: 512 MB storage, shared CPU. Fine for early users.
- **Vercel Hobby**: unlimited static requests; proxy/functions subject to
  fair-use quotas.
- Third-party free tiers change over time — verify limits on the providers'
  pages before relying on them.

## Common issues

| Symptom | Fix |
|---|---|
| `/api/health` fails on Render | `MONGODB_URI` missing/state — check Build Logs |
| Login hangs then errors | Render cold start — retry once; consider a free uptime pinger |
| `CORS: origin not allowed` | `FRONTEND_URL` on Render doesn't match the Vercel URL exactly |
| 502/504 from `/api/*` on Vercel | `BACKEND_URL` not set at deploy time — set it and redeploy |
| Signup works but session lost | Cookies are set via the proxy — make sure the site is opened under the Vercel domain, not a custom domain without re-adding env vars |

## Security notes

- Never put Atlas credentials or API keys in the frontend repo/Vercel
  `NEXT_PUBLIC_*` variables.
- `BACKEND_URL` is server-side (used by the Next rewrite), safe to keep
  private.
- Rotate `JWT_SECRET` if it leaks; all sessions are invalidated.
